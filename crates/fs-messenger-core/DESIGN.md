
## Accepted ideas, first steps (Thread M, 2026-11-08; `requirements.md`, "Accepted ideas")
Pure rules with tests, **not wired** into the repository or a frontend yet:
- **4, read receipts both ways** (`receipts.rs`): `receipts_both_ways(mine, theirs)` is true only when both chose `Shown`; the default is `Hidden`. A provider sends and a frontend shows a receipt only if it is true. The choice per account is not stored yet.
- **9, explain encryption** (`why_plain.rs`, `words.rs`): the reason is a value (`WhyNot`, `Remedy`) chosen by `why_not(Facts)`; the German sentences are in `words.rs` (ADR 0057). `transport-only`, `none` and `unknown` are never shown as encrypted. The facts (is the other side's key known, can the account encrypt) are the provider's to fill in.
- **10, export** (`export.rs`): **JSON Lines, one ActivityStreams 2.0 `Note` per message** (W3C Recommendation). Chosen because our envelope already is AS2 (ADR 0027), nothing is invented, any JSON reader works and a file of lines can be cut, appended and streamed. Mail keeps the original byte for byte in `original` (ADR 0030); **mbox (RFC 4155)** is what to ask a mail provider for and is not rebuilt here. Attachments are not in the file yet (names only would be a half answer); open.
- **1, cool-down and recall** (`cooldown.rs`): `CoolDown::hold/release/send_now/read/recall`, default wait `COOL_DOWN_SECS` (600). A recall works while held or sent and unread. Whether a provider can really withdraw a sent message (Matrix redaction, mail: no) is the provider's to say; mail can only recall while held.
